# 操作手册比对检查报告（自动化实现 vs 手工手册）

- 检查对象：`惠州市中心人民医院电子化采购平台-采购前置操作手册(1).docx`
- 检查方式：重新提取手册全文 + 149 张截图（按章节定位、逐张查看关键页面），
  与 `automation_py` 的流程/接口实现逐步骤比对；并实际下载自动化生成的需求书、审计报告核对内容。
- 检查时间：2026-11-19
- 总体结论：**流程链路无阻断问题（可稳定跑到 status=9），但存在“业务内容真实性”缺口**：
  需求书与审计报告目前只做了“模板生成 + 状态置为已保存”，没有像手册要求的那样按项目实际内容编制/填写；
  若下游要用这些文件做真实招标/审计依据，需要补充内容编制环节。

## 二、需要关注的问题（按严重程度）

### P1（内容真实性问题，影响下游使用）

**1）S15 采购需求书正文没有按项目实际数据编制**

- 实际下载自动化生成的 `采购需求书.docx`（`fileId=FE44FAC0-…`）检查：
  - 只替换了“采购项目名称/采购单位”；
  - “项目概况”“采购方式”为空；
  - **采购预算表仍是模板示例**（包1 心电监护仪、预算单价 8000、金额“不超过 495900 元”），
    与本项目子包（UI自动化项目、实际预算）完全不符；
  - 技术参数、商务要求等均为模板中的示例内容。
- 手册截图（采购需求初稿编制/审查页面）显示：正常流程中需求书的预算表应按项目子包展示
  （包号、名称、数量、单价、预算金额等），并由承办人完善项目概况、技术/商务要求后再提交。
- 影响：流程可以跑到采购中，但生成的需求书不能作为真实业务文件使用。

**2）S16 审计报告正文为空，审计内容编辑环节被跳过**

- 实际下载自动化生成的审计报告（`reportFileId=432B206D-…`）检查：
  - 仅有模板表头与“医务部”等少量信息；
  - 无项目名称、无货物/服务明细、无报审金额/审计建议金额、无审核意见；
  - 报告仅被置为“已保存”（reportStatus=2），并未真正“填写”。
- 手册要求审计员：对每个子包核对/调整审计数量与单价、上传所需附件、选择模板后
  “根据项目实际情况填写”审计报告，再提交主任审批。
- 自动化实际：子包数量/单价未提交调整（后端以默认值计算）、附件未上传、
  审计报告内容未填写（仅审计意见填“同意”）。
- 另外，手册的“推送审计”前有一步“编辑审计内容”（核对采购方式信息、上传需求书关联文件、保存），
  自动化直接调用推送接口（`attachRequirementDocument=1`）跳过该步骤；
  本地接口接受，但真实环境若有保存校验会存在风险。

**3）S20 采购执行申请未编辑/核对**

- 手册：草稿生成后“支持点击【编辑】多次修改”，再提交审批。
- 自动化：直接提交自动草稿，未打开编辑页核对联系人/子包/执行申请表等字段。
- 本地提交成功（说明默认字段满足校验）；真实环境若增加必填校验（如经办人、联系电话、执行申请表），
  可能需要补编辑步骤。

### P2（覆盖范围缺口，手册中存在但自动化未覆盖）

- 预算外采购申请 + 完整采购申请审批流（BT8，含需求科室主任/院领导/财务/行政主管/承办主任指定干事等节点）；
- 组合发起采购申请（多个预算计划一次发起）；
- 线上论证、随机抽取、补抽/续抽、论证延期、专家投票选组长；
- 需求审查“前加签”（主任→干事→主任确认）；
- 审计驳回后修改重提、需求审查不通过/驳回、方式分配驳回、执行申请驳回等逆向流程；
- 其他采购方式：委托采购、竞争谈判、单一来源谈判（需纪要附件）、零星采购、院内议（比）价（需议比价方式）；
- 政府采购路径（需《采购实施计划》+ 政采平台流程）；
- 扫码签名（采购办主任审批可选签名、线上论证报告专家签名）；
- 供应商背调报告（本地 QCC 关闭，未生成）；
- 重新发起调研（响应 0 家场景）；
- 多子包拆分（当前自动化固定单子包，含全部预算计划）。

### P3（实现方式风险，需知晓）

- 大量步骤为“API 直调 + 关键页面校验”，绕过了部分页面级校验（如审计内容保存、审查文件选择弹窗）；
  本地验证通过，换环境/版本时需回归接口契约。
- 本地专用适配：HP→professor MQ 桥接、审计报告 JWT 回调保存、回调端口覆盖、Redis key 同步；
  生产/测试环境需按真实配置替换。
- 审批人固定（zhaoliu/libai/bailu/baiqi/zhoujiu/fgld/fgyld 等），换环境需重新映射。
- 时间窗等待较长（调研 1.5 分钟 + 论证 2 分钟），全链约 5 分钟属业务规则而非性能问题。
- 测试数据清理为软删除，附件文件留在本地文件服务目录。

## 三、建议

1. **若目标是“流程回归/供数造单”**：当前实现已满足，建议在 S15/S16 增加“内容断言”
   （至少校验需求书/审计报告包含项目名称、子包、金额），并在报告中标注“模板内容待人工完善”。
2. **若目标是“生成可用于真实业务审查的文件”**：建议补两块能力：
   - S15：按项目类型选模板后，用项目/子包/预算数据填充需求书（项目概况、预算表、技术/商务要求），
     再“保存并继续”；
   - S16：按审计数据填充审计报告（子包明细、报审/审定金额、审计意见），
     并补“编辑审计内容/关联附件”步骤。
   可基于 `python-docx` 或 OnlyOffice 自动化实现；需要确认模板变量规范（`template_data_snapshot`）。
3. **优先级**：P1-1（需求书内容）> P1-2（审计报告内容）> P2 逆向流程 > 其他方式/政采路径。
4. 可在手册中补充“提交初稿审计后存在承办部门主任编制文件审批（BT14）”的系统实际行为
   （手册只写了提交初稿审计，未提该审批节点，易造成理解偏差）。
