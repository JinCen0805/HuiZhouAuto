## 1. 登录报“服务异常，请联系管理员”

**现象**：所有账号登录失败，registers 日志出现：

```
RpcException: Forbid consumer <IP> access service com.hc.thrift.api.DistributedLogin.DistributedLoginService$Iface ...
```

**原因**：baseserver 的 Dubbo provider 未注册/注册失效（常见于长时间空闲、网络切换、VPN/虚拟网卡变化）。

**排查**：

```powershell
# ZK 中 providers 为空即命中
docker exec hospital-local-stack-zookeeper-1 sh -c "zkCli.sh -server 127.0.0.1:2181 ls '/dubbo/com.hc.thrift.api.DistributedLogin.DistributedLoginService%24Iface/providers'"
```

**修复**：

```powershell
cd D:\Desktop\HuiZhouProject
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\db\infra\local-stack\local-stack.ps1' restart-service -Service baseserver
```

重启后再次自检，登录应恢复。若仍失败，检查 Java 服务是否都存活：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\db\infra\local-stack\local-stack.ps1' status
```

## 2. 专家抽取卡住：`listManualCandidates` 返回“项目不存在”

**现象**：S11 调 `startExtract` 成功但 professor 未建项，`extractPlanStatus=QUEUED`。

**原因**：本地栈默认隔离 HP→professor 抽取建项 MQ；HP 定时任务关闭导致 outbox relay 不执行。

**已做的本地配置**（`local-stack.ps1`，本机 untracked 文件）：

- professor `mq.rabbitmq.vhost=/local-hospital-procurement`（与 HP 共用）
- professor `draw.integration.listener.enabled=true`，并恢复 `spring-rabbitmq.xml` auto-startup
- 执行过 `restart-service -Service professor`

**运行时桥接**：`automation_py/scripts/local_draw_bridge.py` 自动把 HP `draw_integration_outbox`
的待发布消息投递到 RabbitMQ，并补 `hospital.draw.result.queue` 的 `draw.event.#` 绑定。
S11 流程会自动调用（缺少 docker 时跳过）。

**自检**：`env_check.py` 的“抽取建项 MQ 桥接”应为 PASS；否则检查：
```powershell
docker exec hospital-local-stack-rabbitmq-1 rabbitmqctl list_queues -p /local-hospital-procurement name consumers
```

## 3. 审批完成后状态不动（BT14/BT6/BT13）

**BT14/BT6**：business-approval 回调地址必须是本地 HP 端口：

- `hospital.procurement.baseUrl=http://127.0.0.1:17825`
- `government.procurement.baseUrl=http://127.0.0.1:17825`

**BT13（执行审批）**：回调地址必须是本地 PE：

- `execution.procurement.baseUrl=http://127.0.0.1:8088/ProcurementExecution`

以上已在 `local-stack.ps1` 的 business-approval 本地覆盖中配置；改完需：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\db\infra\local-stack\local-stack.ps1' restart-service -Service business-approval
```

历史上出现过的现象：流程实例已结束，但申请单停在 `16`；或 BT13 日志报
`Connection refused: 127.0.0.1:8083`——都是回调端口不对。

## 4. 纪检/审计接口 401“登录已过期”

**原因**：discipline-supervision 本地读 Redis DB7，而 registers 登录写 DB9。

**修复**（自动化已内置）：S16/CLI 启动时会调用
`scripts/local_env.sync_discipline_keys_if_local(cfg)`，把 DB9 的登录 key 复制到 DB7。
2026-11-28 起 `env_check.py` 的纪检鉴权项在 401 时会先自动同步一次再判定（PASS 带
“已自动同步”备注），`pytest` 的 smoke/flows 夹具在角色登录后也会同步一次——本地栈重启后
直接跑回归不再出现成批 401 假失败。
手工修复：

```powershell
$pw = docker exec hospital-local-stack-redis-1 printenv LOCAL_REDIS_PASSWORD
docker exec hospital-local-stack-redis-1 redis-cli -a "$pw" --no-auth-warning -n 9 GET jjzr
# 将返回的 JSON 值 SET 到 -n 7
```

## 5. 审计报告下载/生成失败（Connection refused 7707）

**现象**：纪检平台创建审计报告报
`http://127.0.0.1:7707/doFile/download/ Connection refused`。

**原因**：discipline `application-local.yml` 中 `file.download-base-url` 写错端口。

**修复**：改为 `http://127.0.0.1:17707/doFile/download/?attachmentId=`，然后重启：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\db\infra\local-stack\local-stack.ps1' restart-service -Service discipline-supervision
```

## 6. `数据接口请求异常` / 页面 404

本地 nginx 需有 `/hospital-procurement/` 与 `/ProcurementExecution/` 路由。
`openresty/local-dev/nginx.conf` 已由本地栈维护；若页面接口全 404，先确认：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\db\infra\local-stack\local-stack.ps1' status
```

必要时重启 `hospital-procurement` / `procurement-execution`。

## 8. 长时间空闲后的标准恢复流程

1. `env_check.py`；
2. 有 `服务异常` → 查 ZK providers → `restart-service baseserver`；
3. 检查 `抽取建项 MQ 桥接` WARN → 确认 professor 已按方案 A 重启；
4. 再跑一次默认回归 `pytest -q`（约 4 分钟）确认。
