# 已知限制与能力边界

> 本清单用于交付时明确“自动化能做什么、不能做什么”，避免误用或过度承诺。

## 1. 环境范围

- **仅针对本地环境**（`http://127.0.0.1`）开发与验证；测试/生产环境需另行调整：
  - 回调端口（HP 17825、PE 8088/ProcurementExecution、business-approval 回调地址）；
  - 文件服务地址（上传 7807、下载 17707）；
  - 纪检平台 Redis 库（本地 DB7，生产/测试可能不同）；
  - OnlyOffice 地址与 JWT secret；
  - HP→professor 的 MQ vhost / listener 配置。
- 本地栈包含若干**本机专用修改**（`local-stack.ps1`、`discipline application-local.yml`、
  nginx 本地路由等），不属于业务仓库代码，不应带到测试/生产。

## 2. 业务路径覆盖

- 已覆盖：**自主采购（非政府采购）普通流程**：
  申请 → 纪检分配监督员 → 分包 → 调研信息/公告 → 3 家供应商响应 → 资格性审查 →
  专家抽取（线下+手动+mock 电话确认）→ 线下论证 → 采购需求书 → 审计 →
  终稿确认 → 三方需求审查 → 采购方式分配（比选采购）→ 采购执行申请 → `status=9 采购中`。
- **未覆盖**：
  - 政府采购路径（`governmentProcurement=是`，需要采购实施计划 PLAN 等）；
  - 计划外申请（BT8）、紧急采购、零星采购、产品库议价、价格不合理等分支；
  - 重新招标/流标、驳回后重提等异常分支；
  - 合同、招标、开标、评标、定标及之后的流程。
- 采购方式已支持：自主采购 1 委托、2 比选、3 竞争谈判、4 唯一来源（需会议纪要附件）、
  7 院内议（比）价（需议比价方式）；均已本地全链验证到 `status=9`。
  零星采购(5)、紧急采购(6)、政府采购方式组合仍未覆盖。

## 3. 人工/不可自动化项

- **扫码签名**：采购办主任审批（BT6/BT13）、论证报告专家签名等需要手机扫码手写签名，
  自动化未模拟；本地验证时相应节点按“可选/跳过”处理。
- **真实电话通知**：专家电话确认使用 professor mock 接口（`keypress=1`），不是真实外呼。
- **OnlyOffice 在线编辑**：需求书/审计报告正文内容未做真实业务撰写，仅使用模板生成的默认内容；
  2026-11-24 起审计报告初稿在 HP 侧初始化，本地保存仍通过 JWT 回调协议标记“已保存”
  （生产由编辑器保存触发）；HP 服务需使用 `onlyoffice.jwtSecret` 非空且与回调签名一致
  （本地 `config-dev.properties` 的 `please-change-onlyoffice-jwt-secret`）。
- **附件内容**：统一使用 `fixtures/files/wjc测试文件.pdf`（或 docx），不代表真实业务材料。

## 4. 技术实现选择

- 大量步骤采用“**API 直调 + 关键页面校验**”混合方式（需求书创建/保存、审计推送与审理、
  需求审查、方式分配、执行审批等）。页面上的人工操作路径（如 OnlyOffice 编辑器、
  复杂弹窗）未全部做 UI 级复现。
- 审批人/角色账号按本地库固定（zhaoliu/libai/bailu/baiqi/zhoujiu/fgld/fgyld 等），
  换环境需同步调整 `ROLE_SPECS` 与密码配置。
- 报告只有 JSON/HTML 数据报告，**未采集步骤截图**（`reports/<runId>/screenshots` 为空）。
- 失败重试默认 1 次，只对幂等步骤生效；S01 失败时通过“换下一条预算计划”自愈，
  仍失败则整链失败（不会重复建单）。

## 5. 时间与数据

- 全链耗时约 4~5 分钟，其中约 2 分钟是**等待业务时间窗**：
  调研征集截止（1.5 分钟）+ 论证开始时间（2 分钟）。这是业务规则要求，不是性能问题。
- 测试数据统一前缀 `UI自动化-*`；清理脚本为**软删除**（`is_deleted=1`/`disabled=1`），
  附件文件仍留在本地文件服务目录，需要时手工清理。
- 数据清理脚本只操作本地 Docker MySQL（`hospital-local-stack-mysql-1`），
  默认预览模式，必须显式 `--apply` 才执行。

## 6. 稳定性

- 单次全链已验证成功；连续稳定性受本地栈状态（登录 provider、MQ、OnlyOffice）影响。
  长时间空闲后请先跑 `env_check.py`，按 `docs/环境修复手册.md` 恢复。
- 已知易失败点：预算计划失效（S01 已加换计划自愈）、弹窗残留（已加统一清理）、
  ZK provider 为空（重启 baseserver）。

## 7. 手册比对补充（2026-11-19 复核）

按《采购前置操作手册》全文 + 149 张截图逐步骤复核（详见 `docs/手册比对检查报告.md`），
补充以下已确认缺口：

- **S15 需求书正文**：`createByTemplate` 只替换了项目名称/单位等文本变量；
  预算表、技术参数、商务要求仍是模板示例内容（实测生成文件预算表为“心电监护仪/8000/495900元”），
  未按项目子包/预算数据填充。流程可通过，但文件不可直接作为真实业务依据。
- **S16 审计报告正文**：报告为模板渲染后“已保存”状态，正文无项目明细/金额/审核意见（实测为空表）；
  审计内容编辑、子包数量单价调整、审计附件上传均未执行（本地校验宽松，真实环境可能要求）。
- **S20 执行申请**：自动草稿直接提交，未走手册中的【编辑】核对字段/执行申请表（本地提交成功）。
- **未覆盖流程**：预算外/BT8、组合发起、线上论证、随机抽取/补抽/延期、前加签、
  审计/审查/方式/执行驳回重提、零星/紧急采购、扫码签名、供应商背调报告、
  重新发起调研、多子包拆分。
- 手册未写明“提交初稿审计后存在 BT14 编制文件审批”，实际系统有该节点（自动化已实现）。
